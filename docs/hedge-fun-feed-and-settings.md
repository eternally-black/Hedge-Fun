## Часть 1. Алгоритм формирования ленты

### 1.1. На что оптимизируем (важно до кода)

Инстинкт «гнуть ленту туда, где юзер чаще побеждает» — частично верный, но как первичный сигнал он навредит:

- **Рынки ~эффективны.** На пейпере исход Y/N определяется в основном точностью самого рынка, а не «скиллом» юзера в категории. Высокий винрейт в категории обычно = малая выборка (шум) или ставки на явных фаворитов (90/10). Оптимизация на винрейт смещает ленту к **чалке** — лопсайдным скучным рынкам. Это убивает фан.
- **На старте побед нет.** Ставки резолвятся ≤24ч, приложение новое → в первую сессию персонализировать по победам нечем. А engagement-сигнал (ставит vs скипает) копится с первой карточки.

**Решение:** первичный сигнал — **engagement** (на что ставит, а не скипает; что досматривает). Винрейт по категории — **вторичный, сжатый и капнутый** нюанс, не главный множитель. Всегда держим exploration + потолок на категорию, чтобы лента не схлопнулась в фильтр-бабл.

### 1.2. Стадия 1 — фильтр кандидатов (жёсткие условия)

- ≤24ч до резолюции (блиц).
- Не свайпнуто этим юзером (дедуп).
- Порог ликвидности/качества (отсечь мусорные рынки с кривыми оддсами).
- Уважать настройки: выключенные категории — жёсткий exclude.
- Отсечь «вот-вот резолвнётся» (напр. <15 мин — не успеет стать интересным / может резолвнуться до reveal).

### 1.3. Стадия 2 — скоринг + диверсификация

Каждому кандидату — вес:

```
score =  w_engage  * category_engagement_affinity   # ставит, не скипает (сглаженная)
       + w_explore * exploration_bonus               # категории, что мало пробовал
       + w_fresh   * freshness                        # новые / скоро-но-не-слишком
       + w_quality * liquidity_volume                 # качество рынка
       + w_close   * closeness_to_50                  # ближе к 50/50 = интереснее (опц.)
       + w_win     * shrunk_category_winrate          # ИДЕЯ ЗАКАЗЧИКА: малый вес + сжатие
       + small_noise                                  # анти-детерминизм
```

Веса (стартовая интуиция, тюнить по факту): `w_engage` — главный; `w_explore`, `w_fresh`, `w_quality` — средние; `w_close` — малый-средний; `w_win` — **малый** (приправа, не руль); `noise` — малый.

**После скоринга — диверсификация:** берём топ-N, но с **потолком на категорию** (напр. ≤40–50% колоды из одной) и интерливим, чтобы соседние карты различались. Это защита от схлопывания.

### 1.4. Определения термов

- **category_engagement_affinity** — по категории: доля `bet / shown` (или `bet / (bet+skip)`), **сглаженная** к глобальному среднему (Laplace/Bayesian smoothing), чтобы 1–2 события не давали крайностей.
- **exploration_bonus** — выше для категорий с малой/нулевой экспозицией у юзера (обратное от числа показов).
- **freshness** — выше для свежих рынков / только вошедших в ≤24ч окно; штраф для почти-резолвнутых.
- **liquidity_volume** — нормализованный объём/ликвидность.
- **closeness_to_50** — `1 − |p − 0.5|·2`; рынки около 50/50 интереснее (неопределённость). Опционально.
- **shrunk_category_winrate** — винрейт юзера в категории, **сжатый** (Wilson lower bound или Bayesian shrinkage), чтобы малые выборки регрессировали к среднему: 2/2 ≠ «100% этой категории». Вклад **капнут** малым `w_win`.
- **small_noise** — лёгкий джиттер, чтобы колода не была детерминированно одинаковой.

### 1.5. Cold start

Нет истории → лента **диверсифицированная**: глобальная популярность/ликвидность + freshness + closeness + noise. Персонализация (`engage`, позже `win`) включается после N свайпов (напр. 20), не раньше.

### 1.6. Тонкая колода (fallback)

Если фильтры + настройки оставили слишком мало карт (юзер выключил полкатегорий, а ≤24ч пул тонкий) — релаксить мягкие фильтры (ниже ликвидность-флор / шире окно) или показать честный «тонкая колода» стейт. Пересекается с риском глубины ≤24ч пула (F2 в спеке) — проверять на интеграции.

### 1.7. Фазирование

- **v1 (июль):** `фильтр + дедуп + ликвидность-флор + category_engagement (сглаженная) + exploration + freshness + closeness + потолок категории + noise`. **Без `w_win`** — в первую неделю ему не на чем работать.
- **v1.1 (когда накопятся резолвнутые ставки):** добавить `shrunk_category_winrate` с малым весом. Это и есть «смещение в сторону побед» — но безопасно: сжатое и капнутое.

### 1.8. Входы из настроек (строить вместе с лентой)

- **Тогглы категорий** → жёсткий exclude на Стадии 1.
- **«Персонализировать колоду» (свитч)** → off обнуляет `w_engage` и `w_win`: лента становится нейтральной (только quality/freshness/closeness/diversity/noise). Даёт контроль и снимает ощущение «мной крутят».

## Часть 2. Сет настроек (июль)

Группировка по релевантности июлю (веб, пейпер, push отложен, рефералка/лидерборд — отдельно). Жирным — то, что прямо кормит алгоритм ленты.

### Включаем сейчас

**Контент / лента**
- **Тогглы категорий** (Sports, Crypto, Weather, Esports, …) — показать/скрыть; «скрыть» = exclude из ленты.
- **«Персонализировать колоду»** (свитч) — off → нейтральная лента без engage/win-смещения.

**Опыт / движение / звук**
- **Авто-проигрывание результатов при входе** (вкл/выкл) — управляет reveal-интерстишлом (в духе анти-overload принципа).
- **Reduce motion / меньше анимаций** — доступность; reveal и свайп анимационно-тяжёлые.
- **Звук и хаптика** (вкл/выкл).

**Аккаунт**
- Текущий логин (email/Twitter); адрес embedded-кошелька (показать/скопировать).
- Выйти.

**О приложении / легал**
- Плашка «Paper trading — виртуальные деньги, реальных средств нет» (ожидания + комплаенс-гигиена).
- Terms / Privacy, поддержка (Discord/TG), версия.

### Откладываем (пометить future, не строить в июле)

- Push-настройки (push отложен).
- Размер ставки (зафиксирован фикс $100).
- Светлая тема (только тёмная), язык (только англ.).
- Полноценное удаление аккаунта/данных (можно оставить контакт для запроса).
- Видимость в лидерборде (лидерборд — отдельно).
- Реферальные настройки (рефералка — отдельно).

## Открытое решение

**Дефолт «Персонализировать колоду» — on или off?**
- **On** — сильнее затягивает сразу (хук), engage-сигнал работает с первой недели.
- **Off** — честнее, больше доверия, но слабее хук на старте.

Рекомендация: **on по дефолту + видимый свитч**. Cold start всё равно нейтральный (персонализация включается после N свайпов), так что «on» не значит «сразу манипулируем» — оно начинает работать только когда есть сигнал, а свитч даёт явный контроль. Но это вызов под цель продукта — решение за тобой/заказчиком.
