# Hedge Fun — Admin Leaderboard & Points Tracker (рабочий драфт)

> **Статус: рабочий драфт, НЕ спека.** Проектное предложение под обсуждение и реализацию; по факту билда сводим аудитом и тогда пополняем основную спеку. Не источник правды.
>
> **Это приватный админ-инструмент**, не публичный лидерборд. Публичный лидерборд (F9 в спеке) остаётся отдельным/отложенным. Здесь — внутренний дашборд для команды заказчика.

---

## 1. Что это и зачем

Admin-only дашборд, по которому команда заказчика отслеживает топовых и активных юзеров. **Цель — рост:** находить юзеров с твиттером → публично с ними взаимодействовать (реплаи, ретвиты, фичеринг, награды) → гнать engagement и шиллить продукт в массы. То есть это growth/CRM-lite, а не геймификация для конечного юзера.

## 2. Главное правило — доступ и приватность (критично)

Дашборд показывает **PII**: твиттер-хендлы, возможно email, адрес кошелька, активность, P&L. Поэтому:

- **Только админ-доступ.** Роут и эндпоинты за role-gate, никаких публичных. Это не тот же эндпоинт, что публичный лидерборд.
- В `User` добавить `role` (`user | admin`). Все `/admin/*` — за проверкой роли.
- Приватность: инструмент внутренний. Если что-то из этого позже станет публичным (публичный лидерборд) — показывать только хендл + очки, без email/кошелька/P&L. И не светить публично, что вы трекаете кошельки и P&L юзеров.

## 3. Что показываем (колонки)

**Ядро (v1):**
- Ранг.
- Юзер: display name / аватар (из Privy-профиля), внутренний id.
- **Твиттер-хендл — кликабельный**, ведёт на `twitter.com/<handle>`. Это центральная колонка под цель.
- Очки: **всего + за эту неделю + сегодня** (см. §4 — для шилла важнее «кто разгоняется сейчас», чем статичный all-time).
- Стрик (длина) — длинные стрики = залипшие юзеры, их хорошо фичерить/награждать.
- Last active.
- Флаг «есть твиттер» (для фильтра).

**Опционально / позже:**
- **Разбивка очков по источнику** (свайпы / логин / реф / стрик) — чтобы отличать реально вовлечённого юзера от реф-фармера/бота. Под цель «фичерить настоящих» это полезно.
- Виртуальный P&L / винрейт — шиллабельные истории («юзер поднял $X на бумаге»).
- Кол-во свайпов / активность, приведённые рефералы, осколки/артефакты.
- Дата регистрации, email, адрес кошелька (для дрилл-ина, не в основной таблице).

## 4. Окна времени

`all-time`, `this week`, `today`. Зачем: «кто горяч сейчас / разгоняется на этой неделе» шиллабельнее статичного all-time №1. Сброс окон — по **UTC** (консистентно с остальным приложением).

## 5. Фичи дашборда

- Сортировка по любой колонке, поиск (по хендлу/имени), фильтры: **есть твиттер**, окно времени, мин. очки.
- Клик по хендлу → открыть твиттер-профиль.
- (Позже) **Export CSV** для маркет-команды.
- (Позже / опц.) **CRM-lite**: заметка + флаг «связались» на юзере — трекать, с кем уже взаимодействовали, чтобы не дублировать аутрич.
- В остальном — read-only.

## 6. Модель данных

- `User`: добавить `role` (`user|admin`), `twitter_handle` (nullable — берётся при Privy-логине через Twitter; у email-юзеров пусто), `last_active_at`.
- Лидерборд = агрегирование по существующему `PointsLedger` (сумма всего + по окнам) джойном с `User`. Для MVP-масштаба (Privy free ≈ сотни юзеров) — **живой запрос**, без материализации. Materialized `LeaderboardSnapshot` — только если упрёмся в масштаб.

## 7. Эндпоинты (все за admin-gate)

- `GET /admin/leaderboard?window=all|week|today&sort=&has_twitter=&q=&cursor=` → ранжированные строки с колонками §3.
- `GET /admin/users/:id` → дрилл-ин по юзеру (полный профиль, разбивка очков, история) — опц.
- (Позже) `GET /admin/leaderboard/export` → CSV.
- (Позже) `POST /admin/users/:id/note` / `flag` → CRM-lite.

## 8. Фазирование

- **v1 (сейчас):** admin-gated таблица, ранк по очкам (all-time + week), колонки: юзер / **твиттер (кликабельный)** / очки (всего·неделя·сегодня) / стрик / last active; фильтр «есть твиттер», поиск, сортировка. Живой запрос.
- **Позже:** разбивка очков по источнику, P&L/винрейт, CRM-заметки/флаг «связались», CSV-экспорт, материализованные снапшоты при масштабе.

## Открытые решения

1. **Как выдаётся роль admin** — проще всего на старте: ручной флаг `is_admin` в БД или хардкод-allowlist (email/хендлы команды). Полноценная админ-панель управления ролями — позже.
2. **Twitter-хендл при логине** — подтвердить, что ваш Privy-флоу сохраняет хендл при входе через Twitter (Privy отдаёт связанный аккаунт; нужно класть `twitter_handle` в `User` на логине). Без этого центральная колонка будет пустой.
3. **Публичный лидерборд (F9)** — подтверждаем, что этот админ-дашборд его **не** заменяет: F9 (если вообще делаем) — отдельный публичный, с урезанным PII. Этот — приватный.
